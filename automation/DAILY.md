# 毎日の自動更新手順（Claude の定期実行が読む指示書）

このリポジトリのルートで、次の手順を上から順に実行してください。人への質問はせず、最後まで自分で判断して進めます。

## 1. 準備
- CLAUDE.md を読み、ルールに従う
- automation/topics.json を読む。status が "todo" かつ type が "free" のものの先頭を、今回のネタにする
- automation/insights.md があれば読み、書き方に反映する
- _posts/ の既存記事のタイトルを確認し、内容が重複しないようにする

## 2. 執筆
- 本文は 2,500〜6,000 文字。CLAUDE.md の「文章のルール」「記事の型」を厳守する
- タイトルは32文字以内で具体的に（ネタのタイトル案を改善してよい）
- slug は英小文字とハイフンで、内容が分かる短い英語（例: office-move-budget）
- 関連する既存記事があれば、本文中で1〜2本だけ自然にリンクする（/年/月/slug/ 形式）
- ファイル：_posts/YYYY-MM-DD-slug.md（日付は今日・日本時間）。フロントマター：

```
---
layout: post
title: "タイトル"
date: YYYY-MM-DD 09:00:00 +0900
slug: slug
description: "検索結果に出る説明文（80〜120字）"
affiliate: [関係するキーのみ。なければ空]
tags: [3つ]
---
```

## 3. 品質チェック（公開前に必ず）
次のすべてを満たすまで直す。2回直しても満たせない場合は、そのネタの status を "skipped" にして、次のネタで1からやり直す。
- 定期実行の指示文で渡された NGワードが1つも含まれていない（grep で機械的に確認する）
- 文字数が範囲内
- 根拠のない統計・金額・断定がない
- 体言止めの連続、対句のキャッチコピー、抽象的・情緒的な表現がない
- 読者が今日から実行できる具体的な内容になっている
- 厳しい編集長の目で100点満点で採点し、80点以上

## 4. 記録
- automation/topics.json の該当ネタを status: "done"、slug、postedAt（ISO形式）に更新する
- status が "todo" かつ type が "free" のネタが10本未満なら、既存と重複しない新しいネタを20本追加する（id は連番、type は "free"、テンプレートや表を販売できそうなものは type: "product" にして別に5本まで）
- automation/log.md の先頭に「日付・タイトル・採点・使った広告枠」を1行で追記する

## 5. 公開
- `git add -A && git commit -m "記事追加: タイトル" && git push` で main ブランチに反映する（GitHub Pages が自動で公開します）
- push に失敗したら、`git pull --rebase` してからもう一度 push する
